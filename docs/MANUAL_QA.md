# Ручная проверка Contest Platform

Стенд — Compose с базой `contest_demo`. Для основных проверок используйте своего участника с привязанным Telegram. Администратора, судью и второго участника открывайте в отдельных браузерных профилях. Для изменений создайте отдельный конкурс «Приёмка». Записывайте роль, конкурс, ID задачи и посылки, фактический результат и время. Время в интерфейсе локальное, в выводе seed — UTC.

| Этап | Действие | Что проверить |
|---|---|---|
| 1. Участник и Judge | В «Демо · Тренировка» открыть «Сумма двух чисел». Вставить одну из полных программ ниже с заменой всего текста. | Для каждого языка итог «Принято», 3/3. В истории три разных ID. Повторное решение одной задачи оставляет одну решённую задачу. |
| 2. Гость и вход | В отдельном окне открыть список без входа, затем условие задачи. Зарегистрировать нового участника, выйти, войти по паролю. Проверить неверный пароль и вход через GitHub. | Гостю доступен список и рейтинг, чтение условия требует входа. В шапке и профиле открывается ожидаемый пользователь. После выхода защищённые данные недоступны. |
| 3. Администратор | Создать черновик с названием, описанием, стартом через несколько минут и концом через 10 минут после старта. Попробовать конец раньше старта. Изменить описание и опубликовать. | Некорректный интервал отклонён. Черновик доступен персоналу. После публикации конкурс виден участнику. Публикация сама по себе не открывает отправку. |
| 4. Судья и задачи | Добавить задачу, изменить ограничение, создать пример и скрытый тест. Для импорта проверить JSON и CSV из docs/examples на двух отдельных задачах, затем файл с ошибкой. | Судья видит входы и ответы всех тестов. Участнику видны только примеры. При ошибке импорта количество и содержимое тестов сохраняются. Создавать конкурсы может администратор. |
| 5. Границы времени | Администратором поставить статус active до старта. Участником оставить список, карточку и задачу открытыми на разных вкладках. Проверить до старта, внутри интервала, после финиша и при возвращении из фоновой вкладки. | Для active отображается «Ожидает старта» → «Идёт» → «Завершён». Кнопка доступна в пределах интервала. Вне интервала POST /api/v1/submissions с корректным решением отклоняется сервером. |
| 6. Штраф и Telegram | В новом коротком конкурсе отправить полный текст print(0) на задачу «Сумма двух чисел», дождаться WA. Затем отправить полную правильную программу. Записать время отправки принятого решения. | При WA счёт 0/0. После первого AC — решено 1, штраф равен числу полных минут от старта до отправки плюс 20. В Telegram приходят старт, оба вердикта и окончание. Строки глобального рейтинга и таблицы конкурса сверять отдельно. |
| 7. Ошибки Judge и перепроверка | На своей задаче отправить Python с синтаксической ошибкой, затем программу с исключением. Судьёй запустить rejudge принятой посылки. | Видны ошибки компиляции и выполнения. Перепроверка обновляет вердикт той же посылки. Повторный AC не удваивает число решённых задач. У участника нет права перепроверки. |
| 8. Управление доступом | Вторым участником открыть чужую посылку и административные операции. Администратором изменить роль отдельного тестового пользователя, заблокировать его, проверить доступ и разблокировать. | Чужой код и скрытые тесты защищены в API. Изменение роли и блокировка применяются к выбранному пользователю. Рабочие аккаунты для демонстрации доступны после прогона. |
| 9. Завершение и сохранность | Администратором поставить finished, затем archived; проверить видимость для гостя и участника. Удалить специально созданный пустой конкурс; отдельно попробовать удалить конкурс с решениями. Перезапустить стенд без удаления томов. | Явные finished и archived скрыты от участника по правилам публикации. Исторические результаты входят в глобальный рейтинг. Конкурс с посылками защищён от удаления. После запуска /health возвращает ok, результаты и привязка сохранены. |

## Полные решения задачи «Сумма двух чисел»

В редакторе выделите весь текст перед вставкой. Каждый вариант читает одну пару чисел.

**Python**

```python
print(sum(map(int, input().split())))
```

**C++**

```cpp
#include <iostream>

int main() {
    long long a, b;
    std::cin >> a >> b;
    std::cout << a + b << '\n';
}
```

**Java**

```java
import java.util.Scanner;

public class Main {
    public static void main(String[] args) {
        Scanner in = new Scanner(System.in);
        System.out.println(in.nextLong() + in.nextLong());
    }
}
```

Для повторной короткой проверки выполните `docker compose exec api python -m tools.seed_demo --live check-02`, выбрав свободную метку. Для обычной тренировки подходит уже открытый длинный конкурс.

Если программа упала, откройте её ID в «Решения» и прочитайте последнюю строку вывода. Если посылка остаётся в очереди, проверьте `docker compose logs --since=15m worker`. Для сверки доставки используйте журнал событий:

```powershell
docker compose exec -T db psql -U user -d contest_demo -c "SELECT event_key, status, attempts, delivered_at, last_error FROM notifications ORDER BY id DESC LIMIT 12;"
```
